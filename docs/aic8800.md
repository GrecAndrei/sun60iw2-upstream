# AIC8800D80 workflow

The AIC8800 work is generator-driven. Its input is
`generators/data/aic8800-upstream.json`; regenerate with:

```bash
./scripts/generate-aic8800-upstream.sh
```

The generator updates the source-tree driver under
`drivers/net/wireless/aicsemi/` and generated review artifacts under
`generated/aic8800/`. The generator owns the driver implementation; its two
firmware-protocol source templates live in `generators/templates/aic8800/`.
Do not hand-edit generated output.

## Current capability

The native experimental fullmac path implements the observed AIC8800D80
firmware ABI. Boot handoff binds bootloader ID `0x0182` on SDIO function 2,
uses function 1 for the command transport, starts firmware, then binds runtime
ID `0x0082`. Runtime probe returns `-EPROBE_DEFER` until the boot driver's
handoff completion is ready, so the two SDIO functions do not deadlock.

Implemented host features:

- Station VIF: open/close, scan, connect/disconnect, key install
- Live VIF type change while the netdev is up (`REMOVE_IF` + `ADD_IF`):
  station ↔ monitor (same model as shipped `aic8800_fdrv`; no second
  `mon0` interface)
- Monitor RX with radiotap framing; RX frame size raised to 8192 bytes
- Monitor TX: management and arbitrary MPDU injection via the
  `TXU_CNTRL_MGMT` path; full TX queue drops frames instead of returning
  `NETDEV_TX_BUSY` (so userspace inject does not hang)
- Deferred `cfg80211_scan_done` so scan abort during type change does not
  trip the wiphy mutex lockdep path
- In-band SDIO interrupt only; OOB/host-wake register setup is out of scope

Out of current scope: AP/P2P, multi-VIF, rich PHY capability advertisement,
Bluetooth coexistence bring-up, and suspend/resume claims.

## Hardware state on Orange Pi 4 Pro

Integration kernel: `kernels/a733-v7.1.3`. Board install helper:
`scripts/install-aic8800-modules.sh` (Image, DTB, modules, firmware,
`aic8800-wifi.service`, monitor/station/inject helpers).

Observed on hardware (UART / sysfs evidence from the 2026-07 bring-up):

- `mmc1` enumerates AIC8800 (`c8a1:0182` boot, `c8a1:0082` runtime)
- `wlan0` appears after `aic8800-wifi.service` / module load
- Station scan and association work
- `iw dev wlan0 set type monitor` works while up; channel set needs
  `/lib/firmware/regulatory.db`; tcpdump sees beacons/data on channel
- Inject helper can `AF_PACKET` send probe-req and data MPDUs; TX packet
  counters increment (air confirmation is a separate RF check)

Preferred firmware name is
`aic8800d80/fmacfw_8800d80_u02.bin` (see
`generators/data/aic8800-upstream.json` fallbacks). No firmware blob is
tracked in this repository.

## Firmware and device test helpers

```bash
# After wlan0 exists:
wifi-monitor.sh [channel]    # stop station userspace, set monitor + channel
wifi-station.sh              # back to managed + restart wpa/dhcpcd
wifi-inject-probe.py [wlan0] # raw-socket inject with timeout (no hang)
```

Board scripts live under `scripts/` and are installed to `/root/` and
`/usr/local/bin/` by the install helper. Keep network credentials out of
the tracked install script; configure `wpa_supplicant` on the rootfs only.

## Rail ownership rule

An AXP8191 output must never be named as `mmc1`'s `vmmc-supply` or
`vqmmc-supply`. The working Orange Pi 5.15 board DTS wires **no** MMC
supplies on `sdc1`. PG/PM IO comes from BLDO5/CLDO1 at 1.8 V
(`regulator-always-on`), and chip enable is PM1 via `mmc-pwrseq-simple`.

A rail declared in DT without `regulator-always-on` is switched off by
`regulator_init_complete()` once its use count reaches zero.
`regulator-boot-on` does not prevent this. Because A733 pinctrl sets
`SUNXI_PINCTRL_AUTO_POWER_SWITCH`, `sunxi_pmx_request()` never claims
`vcc-pg-supply` or `vcc-pm-supply`, so BLDO5 and CLDO1 must both be
`regulator-always-on`. In auto-hard mode A733 leaves `PIO_POW_MOD_SEL/CTL`
under hardware ownership. The PIO layout is sun60iw2 TYPE_4
(`SUNXI_PINCTRL_SUN60_LAYOUT`): bank stride `0x80` from base `0x80`, and
`PIO_POW_MOD_SEL/CTL` at `0x40`/`0x48`. Do not use D1 `NEW_REG_LAYOUT` or
A523 `ELEVEN_BANKS` for the main PIO.

CPU DVFS rails DCDC3 (big) and DCDC5 (little) are declared separately for
cpufreq; still do **not** declare DCDC1 (known AXP probe abort when
`get_voltage` fails with `apply_uV`). See [`hardware.md`](hardware.md) and
[`guides/thermals.md`](guides/thermals.md).

PB4 is not a Wi-Fi enable; it is shared with the I2S0 clock function.

## Vendor reference (behavior only)

Orange Pi 1.0.6 Ubuntu image SHA-256
`0b5f284f943d7d19f7a00c317f396931b0e8e7e9d593922c342699f09ab9340b`.
Shipped `aic8800_bsp.ko` imports `sunxi_wlan_set_power()`,
`sunxi_wlan_get_bus_index()`, and `sunxi_mmc_rescan_card()`. Observed power
path: wait 50 ms after PM1, MMC redetect, up to 2 s for `c8a1:0182`;
power-off waits 100 ms. These observations constrain regulator/GPIO/MMC
usage; they do not justify importing BSP APIs or source.
