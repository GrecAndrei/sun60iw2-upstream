# AIC8800D80 workflow

The AIC8800 work is generator-driven. Its input is
`generators/data/aic8800-upstream.json`; regenerate with:

```bash
./scripts/generate-aic8800-upstream.sh
```

The generator updates the source-tree skeleton under
`drivers/net/wireless/aicsemi/` and generated review artifacts under
`generated/aic8800/`. Do not hand-edit either generated output.

## Current capability

This is compile-tested transport scaffolding, not a functional WiFi driver.
The AIC firmware command, confirmation, and data-frame protocols have not been
implemented. Consequently scan, connect, disconnect, and netdev open return
`-EOPNOTSUPP`; received proprietary transport messages are drained and dropped
instead of being misidentified as Ethernet frames.

Bootloader-mode device ID `0x0182` is also rejected with `-EOPNOTSUPP`. Firmware
must not be copied directly to a large SDIO function address: the real device
uses confirmed debug-memory block-write commands before re-enumerating as the
normal runtime device (`0x0082`). Implement that command protocol before
enabling firmware download or claiming hardware WiFi support.

The Orange Pi 4 Pro description uses PM1 as the active-high `WL_REG_ON` signal
(expressed as an active-low reset to `mmc-pwrseq-simple`), PM0 as host wake, and
a 1.8 V fixed-domain placeholder until the AXP8191 regulator driver is ready.
PB4 is not a WiFi enable; it is shared with the I2S0 clock function.

To export the skeleton into a disposable Linux tree:

```bash
./scripts/export-aic8800-kernel-skeleton.sh /path/to/linux
```

The DTB and compile checks modify their target Linux tree and write local,
ignored evidence under `.tmp/validation/`:

```bash
./scripts/check-aic8800-dtb.sh /path/to/linux
./scripts/check-aic8800-skeleton-full.sh /path/to/linux
```

Those checks establish only the recorded compile/DTB result. Hardware behavior
requires a separately captured test log. The generated live report deliberately
does not promote prior JSON snapshots into a hardware-validation claim.
